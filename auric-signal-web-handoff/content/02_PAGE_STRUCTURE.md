# Page Structure — AURIC SIGNAL

Route target: `/work/auric-signal`

The desktop sidebar contains eight chapter anchors. Secondary headings remain in the main content only.

| Anchor | Sidebar label | Purpose | Primary assets |
|---|---|---|---|
| `overview` | Overview | Establish project, role, scope, prototype, and outcome | `01-home.png`, selected system screens |
| `context` | Context & Opportunity | Define interpretation gap, HMW, constraints | Native text and a cropped Priority Signal detail from `01-home.png` |

## Project introduction

Order:

1. Breadcrumb: `Work / Product Design / AURIC SIGNAL`
2. Project title
3. One-sentence positioning
4. Metadata: type, role, duration, year, status
5. Prototype link
6. Hero media

Do not place the full project introduction in the sidebar.

## Content emphasis

- 15% — Overview and context
- 20% — Research and product strategy
- 25% — Design development and key decisions
- 30% — Core interactive journey
- 10% — Trust, outcome, limitations, and future validation

Prioritize Key Design Decisions, Core Hero Journey, AI Explanation, Scenario Evaluation, and Trust/User Control. Home, Assets, Watchlist, and Profile prove product completeness but should not receive equal narrative weight.

## Experience chapter presentation

Desktop may use a sticky explanatory column and sequential UI cards. This behavior is local to the chapter, not a global page effect. The DOM order must remain linear:

1. Awareness — Home
2. Explanation — Signal Detail
3. Evidence — Signal Detail Evidence
4. Evaluate — Scenario Simulation
5. Inspect — Why Auric Expanded
6. Compare — Rebalancing Impact
7. Confirm — Strategy Saved

Mobile converts this to ordinary vertical content. Reduced Motion removes transforms and stacking.

## Development chapter presentation

- Show Early Exploration as the main comparison board.
- Use Iteration Wireframes to connect structure to the final journey.
- The full Refined Hierarchy asset contains unverified “Findings from Testing.” Do not show that panel. Either crop to the central hierarchy only or do not publish the asset.
- Core User Flow is dense: show a simplified native summary and make the complete asset available in ImageViewer.
- `05-sketch.png` remains reference-only until the owner confirms that it is an authentic original process photograph.

## Outcome presentation

Use a compact system overview rather than repeating every large screen. Suggested supporting images: Insights, Assets, Watchlist Alerts, and Profile. The profile asset is low resolution and must remain small.
